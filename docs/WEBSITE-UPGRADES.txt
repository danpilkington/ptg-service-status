Status website upgrades - October 2026

Email subscriptions
- Users select services at /subscriptions.html and confirm a one-use email link.
- Incident updates, resolutions and maintenance notices go only to confirmed subscribers.
- Re-submitting and confirming changes preferences; every update has an unsubscribe link.
- Uses existing Azure credentials and Graph Mail.Send permission. Set SUBSCRIPTIONS_ENABLED=true,
  SUBSCRIPTION_EMAIL_FROM (defaults to WELCOME_EMAIL_FROM), and SUBSCRIPTION_PUBLIC_URL to the public HTTPS root.
- Microsoft notices are emailed only when PTG impact is confirmed; stale provider reports do not generate updates.
- The first background snapshot establishes a baseline and does not email historical incidents.
- Private subscription data and the durable outbox use the existing SQL/file storage.
- Failed deliveries retry with backoff; 20 messages per background minute maximum. A crash after Graph accepts
  a message but before delivery is recorded can cause a duplicate, so delivery is at least once.
- The subscription queue and address list are included in encrypted recovery exports (format version 2).
  Older version 1 recovery archives remain readable. File storage must back up subscriptions.json too.
- Latest 100 unsubscribe links per subscriber remain valid, plus the confirmation-page unsubscribe link.
- SQL startup extends the Documents name constraint with subscriptions. If the runtime account cannot alter
  the schema, run node database-setup.js upgrade using the existing database administrator before restarting.

Maintenance calendar
- Open Planned maintenance calendar on the public page for a month view in the visitor's local timezone.
- Download upcoming work or a specific event as an .ics file compatible with Outlook.
- Import downloads again after a schedule changes; downloaded calendar files do not refresh themselves.

Service check timestamps
- Service cards show the actual automatic/provider check time and a stale marker when applicable.
- Manual services are labelled as manually reported, without implying an automatic health check.

Incident templates
- Templates now cover outage, intermittent service, sign-in, connectivity, cause identified, recovery monitoring
  and service restored. Review and confirm the description and impact before publishing.

Admin SSO diagnostics
- Administrators see SSO configuration, token-validator readiness, linked account count, last successful sign-in,
  and up to three recent safe failure explanations in the existing integration-health panel.
- The server retains the latest 30 failure records in memory; these reset when the app restarts.
- Diagnostic records include numeric Microsoft error codes only, never credentials, tokens or raw provider text.

Mobile administration
- Scrollable section navigation stays at the top; publishing controls stay at the bottom.
- Forms, template controls and buttons fit narrow screens, with larger touch targets and safe-area spacing.

Deployment
- Restart the Node website after copying the updated files and enabling subscription settings.
- Validate one real email confirmation and one Microsoft sign-in after restart; automated checks use test mail delivery.

Subscriber management, ownership, dependencies and incident review reports

Administrators have Subscribers and Incident reviews sections in the admin navigation.
- Subscribers: search/filter addresses, view confirmed/pending/paused/expired counts, queued delivery
  and failure counts, pause/resume confirmed subscribers, retry queued failures, and remove addresses.
- Pausing cancels queued emails. Resuming covers future notices; old missed notices are not replayed.
  An email already in flight cannot be recalled. A pending address cannot be activated by an administrator;
  it must confirm through its email link. Actions are audited by subscriber ID, without duplicating addresses.
- Delivery timestamps mean Microsoft Graph accepted the email, not guaranteed inbox delivery. Tracking
  starts with this update; earlier deliveries may show no timestamp. Confirmation email failures are shown.
- Service editor: record a public owner team, an administrator-only private escalation contact, and
  dependencies on other PTG or Microsoft services. Team/dependency changes follow existing publishing
  approval rules. Private contacts can only be changed by administrators.
- Dependency validation rejects circular chains, self references, duplicate or missing services. Remove
  references before deleting a service. The public page shows direct and indirect dependency warnings,
  without automatically changing service status. The Affected filter includes dependency warnings.
- Private escalation contacts are excluded from public responses, editor views and browser draft recovery.
  Unsaved contact edits must be reapplied after draft recovery.
- Incident reviews: administrators review resolved PTG incidents, record impact, cause, resolution and
  lessons, and track up to 30 follow-up actions with owners, due dates and completion status. Reviews
  are saved separately from public notices and audited. Reopened incidents cannot have reviews saved
  until they are resolved again. The report uses the latest published incident timeline.
- Download the saved review as a standalone HTML report; open it in a browser to print or save as PDF.
  Elapsed incident duration is not measured service outage duration.

Deployment for this update: run node database-setup.js upgrade under the existing server database
  administrator/service account and restart the Node website. The reviews storage document is added
  alongside subscriptions; existing records are retained. The admin editor requires backend version 9.
  Recovery exports now use version 3 and include reviews; versions 1 and 2 remain readable. Back up
  reviews.json with the other private sidecars on file-backed installations.

PAGE FOLDERS
Pages and their dedicated browser scripts now live in pages/status, pages/info, pages/maintenance, pages/subscriptions and pages/admin. Shared assets and server modules remain at the project root. Existing website URLs and Microsoft sign-in callbacks are unchanged. Deploy the pages directory and updated server.js together, then restart the service. No database upgrade is needed for this folder change.
